OSF Settings 1.2.0

- Added shared settings pages: add-ons can place their controls on another
  mod's page while keeping their own saved values, actions and hotkeys.
  Contributed settings identify the mod that provides them.
- Added optional page integrations. When the host is absent, integration
  controls, hotkeys and launchers are hidden without losing saved values.
- Added schema-based dependency checks for missing mods and minimum versions.
  Reports refresh when runtime providers change and retain valid dependency
  guidance even when a consumer's settings schema fails validation.
- Redesigned Mod Issues around the problem, affected mods and suggested fix.
  Dependency details show installed/required versions and can open a Nexus
  Mods page when the provider supplies its Nexus ID.
- Added each mod's interface launchers to its settings page, above its groups.
- Fixed localization falling back to English when the game's language is
  overridden in an INI file, including Japanese mod-manager profiles.
- Fixed garbled count labels when translated text precedes a placeholder.
- Kept long action names inside the keybinding conflict dialog.
- Moved Open Mod Settings to the top of the keybindings list.
- Right now moves from the sidebar into a settings panel without starting
  editing; Accept enters editing. Fixed held Accept state when leaving launchers.
- Reduced repeated translation scans, snapshot copying and provider replacement
  work, especially for large settings collections. These are menu/data-path
  improvements; no gameplay FPS improvement is claimed.
- Added an editor JSON Schema for mod authors, including dependency metadata
  and shared-page declarations. Existing integrations must opt in to these
  features; OSF Settings does not inspect every installed mod's dependencies.

For mod authors: replace expectedSettingsVersion with a dependencies.osfsettings
minimum. The old field is ignored in 1.2.0; it can remain alongside dependencies
for older hosts. The former special-case OSF UI DLL version check is removed;
consumers now declare that dependency using the osfui settings mod ID.

Upgrade by replacing the previous OSF Settings installation. Keep existing
settings and Starfield Controls files. Restart Starfield after updating.
OSF UI is not required. See README.txt for requirements and known limitations.
